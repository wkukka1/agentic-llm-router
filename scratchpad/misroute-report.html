Where NIRT Misroutes

On RouterBench test the NIRT router has collapsed to a near-constant policy: it sends 98.5% of queries to GPT‑4, the single best-on-average model. Its accuracy against the oracle is indistinguishable from — fractionally worse than — an unconditional “always GPT‑4” rule.

Every model in the pool sees the same estimator: NIRT predicts E[Y | q, m] for each candidate, then routes to argmaxm. The oracle is the cheapest model that actually attains each query’s best observed score — an evaluation target only, never seen in training. Regret is the quality the router left on the table: maxm y(q,m) − y(q, m̂). Total regret across the split is 936 quality-points; the sections below account for where it comes from.

01The router uses one model

NIRT’s selections against how often each model is a best option for the query. The pool is diverse — every model is the (tie-inclusive) best on 35–82% of queries — but the router never learns to reach for any of them.

02The errors are total, not marginal

Regret among the 1,320 mis-routes is sharply bimodal. A third are near-misses; the rest are complete — the router picked a model that scored ~0 where another scored ~1.

03It concentrates on a few task types

Regret by dataset. Two multiple-choice benchmarks — HellaSwag and grade-school math — account for 41% of it. These are exactly the tasks where GPT-4 has idiosyncratic wrong answers a smaller model happens to get right.

04Every wrong turn goes the same direction

On mis-routed queries: how often each model was wrongly picked vs how often it was a best option the router passed over.

05The right model is usually its second choice

On mis-routes, where NIRT ranked the best model it could have picked, within its own 11-way predicted ordering.

06Diagnosis

The objective rewards calibration, not ranking

NIRT is trained with per-cell soft_bce on y(q,m). That loss is minimised by getting each model’s marginal probability right — and the lowest-loss way to do that, given a weak θq, is to output each model’s base rate. GPT-4’s base rate is highest, so argmaxm picks it every time.

In the logit am·θq − bm, the per-model bias bm dominates and the query term barely moves the ordering. Going from K=2 to K=16 adds latent capacity but not ranking signal — regret is unchanged — so the bottleneck is the training target, not the model size.

The router already contains the information (Section 05): it just needs a loss that is paid to order models within a query.

  • P5 Switch to a routing-aware loss — pairwise / listwise / bce_pairwise with sampler=query — and select on val_metric=regret, not BCE.
  • check Track any-best hit rate and the selected-model mix during training; a healthy router should spread across the pool the way the teal bars do.
  • data Over-weight the bimodal tail — HellaSwag, grade-school-math, MMLU-law — where a cheap model beats GPT-4; those queries are the entire regret budget.
  • cost Even a correct quality router should be run cost-aware (λ>0): the oracle matches its quality at $1.50/1k against $5.67.
